# 公文寫作場景涵蓋度盤點

盤點日期：2026-09-06。基準：修改前 v1.4.1。此表盤點實際寫作決策，不以觸發詞數量代表支援完整度。

「已有」表示有可操作的寫法；「部分」表示僅列文別或通用模板；「缺漏」表示缺少該場景的判斷及撰寫指引。新增指引不等於已覆蓋每個機關的專門法規。

## 本次已補強

| 場景 | 原覆蓋 | 原缺口 | 本次處理 |
|------|--------|--------|----------|
| S01 催辦、催復、催報 | 缺漏 | 未介紹催辦案件通知單，容易一律產出函 | 原期限、未復事項、定型化通知單及新增要求的分流 |
| S02 展期 | 缺漏 | 未分機關請求展期、依法申請處理期間及陳情期限 | 三種期限來源、核准狀態與民眾申請的角色分流 |
| S03 補正通知 | 缺漏 | 有核准申請場景，無可操作的補正通知 | 缺漏對照、依據、期限起算、補件方式及逾期效果 |
| S04 否准／部分准許 | 部分 | 有否准用語與裁處書，未處理一般申請的處分判斷 | 決定範圍、理由對應及個案救濟教示 |
| S05 陳述意見通知 | 缺漏 | 容易由補件或裁罰模板替代 | 處分前程序、通知事項及未陳述效果 |
| S06 陳情答復／移轉 | 部分 | 有民眾陳情書與單純移轉，缺機關答復流程 | 逐點回應、移文單、通知當事人及跨機關分工 |
| S07 更正／補送附件 | 缺漏 | 「幫我改」未區分草稿與已發文 | 版本識別、一般錯誤與實質變更處分的界線 |
| S08 便簽／會辦意見 | 部分 | 便簽僅列名，無會辦意見及主辦彙整指引 | 便簽骨架、送會問題、意見依據、歧見處理 |
| S09 會勘通知／紀錄 | 部分 | 有會勘關鍵字但無通知及紀錄的實際寫法 | 套通知單格式，區分觀察、主張、待查及結論 |
| S10 會議異動／追蹤 | 部分 | 僅有初次通知及紀錄模板 | 改期取消、紀錄更正、核定狀態及決議追蹤 |
| S11 箋函 | 部分 | 僅列名且限縮成首長禮節性書信 | 改為個人名義洽復公務，補結構及機關函分流 |
| S12 公務電話紀錄 | 缺漏 | 無通話紀錄格式及使用界線 | 必要欄位、確認狀態及附卷處理 |

規範入口：[公文案件場景補充指引](../references/official-scenarios.md)。單檔版為附錄六，多檔 skill 依場景選讀。原有13種教材場景保留，並未宣稱新增12組與它們完全不重疊。

一併修正：先簽後稿的產出順序、會議紀錄「紀錄」欄、通知單行款、救濟教示錯誤的過度概括、逕予存查的手冊點次，以及箋函適用範圍。政府其他文件是本專案的閱讀分組，不能概括稱為法定分類上的「非公文」。

## 仍未完整覆蓋，建議下一批處理

| 優先順序 | 場景 | 現況與下一步 |
|----------|------|--------------|
| 高 | 法規命令／行政規則的訂定、修正、廢止與預告 | 有令、公告通用格式；仍缺預告與發布分流、修正總說明、條文對照表、發布及生效日期檢核。須核對法制作業規定 |
| 高 | 多機關會銜、代擬代判、分稿及一案多文 | 本次僅釐清會辦不等於會銜；仍需會銜順序、各機關文號／署名及核判流程，不能只增加一個標題 |
| 高 | 會議提案、業務說帖、專案調查／評估報告 | 尚無獨立指引；應分清提案的待決事項、說帖的協調目的、報告的事實與證據 |
| 高 | 政府資訊公開、行政程序閱卷、檔案應用 | 有申請書通用模板，未分三種程序的資格、限制、費用、准駁及救濟 |
| 中 | 政府採購及履約公文 | 欠缺招標疑義／異議答復、履約催告、驗收缺失改善、契約變更等；須先取得採購階段與契約，避免把契約通知一律當行政處分 |
| 中 | 訴願答辯、行政訴訟答辯及卷證檢送 | 有訴願書及決定書，無機關端爭點答辯、證據對照與卷證目錄；須另查法定格式 |
| 中 | 出國報告、施政／業務計畫、澄清聲明稿 | 描述已列出部分名稱，參考檔仍無專章；屬「宣稱可觸發，但專用指引未完成」 |
| 中 | 議會／立法院質詢書面答復及列管回復 | 施政報告不能替代逐題答復；需查明對象、答復期限、承諾事項及列管格式 |
| 中 | 災害與緊急事件公文 | 需要區分速報、請求支援、停班停課通知與後續追報；不能自訂發布權限或以一般公告代替專用程序 |
| 中 | 公私立學校、補助機關與受補助者往復 | 尚缺常見隸屬關係辨識範例；應防止把「有補助／受監督」直接推論為上行文的隸屬關係 |

純學術論文、商業企畫、求職文件及私人書信仍維持原排除範圍。

## 維護與驗證

新增精確法條或點次先登記 [CITATIONS.md](../CITATIONS.md)，規範從 `references/` 修改；再更新入口及必要的 LITE 摘要，執行：

```bash
python3 scripts/build.py
python3 scripts/check_consistency.py
python3 scripts/package.py --check
```

上述檢查驗證生成同步、版本及包內檔案，**不等於模型已通過公文寫作測試**。行為檢查題目與判準另見 [scenario-evaluation.md](scenario-evaluation.md)，實際試跑應記錄模型、版本、輸入及輸出，不把題目存在當成通過。
